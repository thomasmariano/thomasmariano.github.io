MEOSAR Mission Scheduler & Simulator

Two integrated applications: a scheduler for building satellite tracking plans and a simulator for exploring those plans over time.

SOFTWARE · AEROSPACE · SYSTEMS

Mission scheduler

A Python-based mission scheduling application designed to analyze satellite visibility, antenna availability, and mission events for MEOSAR operations.

I developed a graphical workflow that brings mission configuration, satellite selection, antenna assignments, and coverage analysis together. Its exported tracking schedules can be loaded into the companion MEOSAR Mission Simulator for visual review.

Technologies: Python, PyQt6, Skyfield, CelesTrak TLE Data

The MEOSAR Mission Scheduler is a proprietary application developed for NASA's Search and Rescue program. It is not publicly available.

My work

Scheduling logic and configuration

I built the scheduler around a configurable mission window, mission and ground locations, satellite selection, and antenna availability. The workspace brings the resulting assignments and visibility plots together so a tracking plan can be reviewed alongside its coverage.

Mission configuration
Set an event time in UTC, define coverage before and after the event, select mission and ground sites, and add weighted alternate coverage locations.
Tracking schedules
Review satellite assignments by antenna on a time-based chart, with controls to edit and export the schedule.
Visibility analysis
Compare selected-satellite and all-satellite mutual-visibility timelines, alongside satellite counts throughout the mission window.
Orbit-data review
Select satellites by NORAD or MEOSAR ID and review TLE epochs against a configurable age cutoff.

Implementation decisions

Scheduling under constraints
I used a bounded beam search alongside a greedy baseline and an antenna/satellite matching seed. Candidate assignments account for mutual visibility, antenna band compatibility, duplicate assignments, and contact retention. This is a scheduling heuristic rather than a guaranteed global optimum.
Data that can be traced
TLE handling includes source records, epoch-age checks, and missing-satellite reporting. Machine-readable schedule exports are kept separate from diagnostics, with companion metadata carrying the simulator’s mission context.
Shared logic between applications
The scheduler and simulator share visibility calculations and UTC handling. The Python-to-JavaScript bridge passes orbital data as JSON, while diagnostics help investigate disagreements in timestamps, satellite records, or observer settings.
Code and configuration maintenance
I split large interface and data-management files into smaller components, separated packaged resources from writable configuration, and used temporary files with atomic replacement for configuration writes.

Integrated application / Simulation & visualization

Integrated mission simulator

I built the simulator into the scheduler with an embedded preview and a dedicated simulator window. The two applications exchange assignment text and companion mission metadata, use UTC throughout, and share visibility calculations.

The Python backend supplies orbital data to an HTML, CSS, and JavaScript globe dashboard embedded through PyQt6-WebEngine. This connects the scheduler’s tracking assignments to interactive satellite and coverage views.

Playback, coverage, and diagnostics

I developed the simulator as a companion to the scheduler. It loads a tracking schedule and TLE orbit data into a globe-based playback workspace, bringing satellite positions, ground locations, coverage, and assignment status into the same view.

The scheduler creates the tracking plan; the simulator provides a way to inspect how that plan relates to the simulated geometry throughout the mission window.

Schedule and orbit data
Load exported tracking schedules and import or refresh TLE data for the simulation.
Playback and satellite layers
Step through mission time, adjust playback speed, and control the display of satellite orbits, tracking, and coverage.
Coverage and assignment review
Inspect location coverage counts, the assignment timeline, and scheduler/simulator checks alongside the globe.
Inspection and diagnostics
Review satellite information and engine diagnostics in the simulation workspace.

Simulator technologies: Python, PyQt6-WebEngine, JavaScript, HTML/CSS, Canvas, SGP4, Skyfield, JSON.

SOFTWARE · ORBITAL ANALYSIS · SAR

Local GNSS-to-TLE Generation System

I developed a local orbital-data system used for search-and-rescue operations across all MEOSAR satellites. It converts GNSS broadcast navigation data into SGP4-compatible Two-Line Element sets (TLEs), providing an internally maintained source of orbital data for MEOLUT/MCC systems.

The pipeline ingests RINEX navigation records from SecureSync, calculates satellite positions and velocities, transforms Earth-fixed states into TEME coordinates, and fits orbital elements using numerical least squares. It serializes the results as TLEs with checksums and publishes updates over the internal network.

My work covered navigation-data processing, coordinate transformations, orbital fitting, and validation against independent precise SP3 orbit products. The system maintains local orbital updates without recurring Internet requests to external TLE catalogs.

Technologies: Python, GNSS, RINEX, SGP4, Astropy, numerical least squares, SP3 orbit validation, SecureSync.
